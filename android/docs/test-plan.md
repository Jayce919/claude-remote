# Claude Mobile 全量测试方案

## 1. 被测范围

两件东西，一套方案：

| 组件 | 位置 | 技术栈 |
|---|---|---|
| 服务端 | `server/` | Node 22.5+ + Claude Agent SDK + cc-switch 代理 |
| 安卓端 | `android/` | Kotlin 2.1 + Jetpack Compose，包名 `com.clauderemote.app` |

不在范围内：模型回答质量、cc-switch 上游可用性、Tailscale 组网本身（只抽查连通性）。

## 2. 现状盘点

| 项 | 现状 |
|---|---|
| 服务端自动化 | 5 个手工脚本（`test-e2e/image/permission/resume/tailnet.mjs`），无断言、无统一入口、跑完靠肉眼看输出 |
| 客户端自动化 | 0。没有 `test/`、`androidTest/` 目录，`build.gradle.kts` 里也没有测试依赖 |
| 界面验证方式 | 模拟器 + `adb exec-out screencap` 人工看图，不构成可回归的基线 |
| 已知缺陷 | ① 权限模式「逐步询问」不弹确认卡（未定位）② 行内公式边界（转义、纯数字误判）③ 换图标后桌面缓存需卸载重装 |
| 覆盖盲区 | 多会话并发、SSE 断线重连、长会话性能、平板/横屏、系统无障碍字号 |

## 3. 测试环境

### 3.1 环境清单

| 角色 | 配置 |
|---|---|
| 服务端 | Node 22.5+（`node -v` 确认），端口 8787，cc-switch 桌面端路由 |
| 模拟器 | AVD `claude`，Pixel 6 骨架，`wm size 1216x2640` + `wm density 460`（对齐真机） |
| 真机 | 6.31 英寸 2640×1216（按你的机型调整），Tailscale 同账号 |
| 网络 | 本机回环（模拟器 `10.0.2.2`）、tailnet HTTPS 两条路径都要测 |

### 3.2 环境准备

```bash
# 服务端
cd server && start.cmd

# 模拟器对齐真机分辨率
adb shell wm size 1216x2640 && adb shell wm density 460

# 安装（换过图标的版本必须先卸载，否则桌面缓存不刷新）
adb uninstall com.clauderemote.app; adb install -r app-debug.apk
```

### 3.3 环境复位（每轮测试前）

- 客户端偏好复位：`adb shell run-as com.clauderemote.app` 写入空 prefs，或设置面板里断开连接重连
- 服务端数据复位：备份并清空 `server/data/conversations.json`
- 模拟器分辨率复位：`adb shell wm size reset && adb shell wm density reset`

## 4. 分层策略

| 层 | 内容 | 手段 | 频率 |
|---|---|---|---|
| L0 | 构建与静态检查 | Gradle assembleDebug/assembleRelease、lint | 每次改动 |
| L1 | 服务端接口契约 | curl / node 脚本，断言状态码与字段 | 每次服务端改动 |
| L2 | 服务端流程集成 | SSE 事件序列、工具、权限、恢复 | 每次服务端改动 |
| L3 | 客户端逻辑单测 | JUnit（新增）测纯函数与状态折叠 | 每次客户端改动 |
| L4 | 客户端 UI E2E | 模拟器 + adb 脚本 + 截图归档 | 每个里程碑 |
| L5 | 真机验收 | 手工清单 | 发版前 |
| L6 | 非功能 | 性能、内存、耗电、长稳 | 发版前 |
| L7 | 安全与隐私 | 存储、传输、WebView 权限 | 发版前 |

## 6. 自动化建设

现状是零自动化，这轮要补三样，按投入产出排序：

### 6.1 服务端：统一 runner（半天）

把 5 个脚本收进 `test/run.mjs`，每个用例带断言与退出码，输出 JUnit 风格汇总：

```
test/
├─ run.mjs          统一入口，一条命令跑完
├─ cases/api.mjs    接口契约
├─ cases/sse.mjs    事件顺序
├─ cases/tool.mjs   工具与权限
└─ cases/recovery.mjs 断线与恢复
```

判定标准：`exit code 0` 才算通过，替代现在「人眼看输出」。

### 6.2 客户端：JVM 单测（1 天）

先给不依赖 Android 框架的纯逻辑补测，性价比最高：

| 目标 | 用例 |
|---|---|
| `Markdown.toBlocks` / `splitMath` | 公式识别边界（`$x$`、`$5`、`\$` 转义、跨行） |
| `spansToHtml` | 加粗/斜体/代码/链接转义正确，`<` `&` 不破坏 HTML |
| `ChatViewModel` 事件折叠 | 占位消息接手、工具结果回填、pending 作用域 |
| 颜色转换 | `toArgb()` 输出的十六进制与主题色一致 |

需要新增 `testImplementation(junit)` 与 `kotlinx-coroutines-test`；ViewModel 需要 Robolectric 或先抽出纯函数状态机。

### 6.3 客户端：UI 冒烟脚本（半天）

用 adb 串一条 P0 冒烟链，产物归档到 `docs/test-artifacts/`（不再落桌面）：

```
启动 → 空态截图 → 发一句话 → 等回复 → 截图 → 开抽屉 → 截图 → 开设置 → 截图
```

配合 `adb shell uiautomator dump` 做文本断言（如「顶栏副标题包含真实模型名」），失败即退出非零。

## 7. 缺陷回归清单

本会话已修复、每轮必须回归的项：

| 缺陷 | 现象 | 回归用例 |
|---|---|---|
| 公式被裁成横条 | CSS 未内联 + CSS 像素当物理像素换算 | MD-04 |
| 流式回复重复两条 | 增量早于 assistant-start 到达 | TOOL-04 / UI-07 |
| 选框卡在历史里重复渲染 | pending 表未按消息作用域过滤 | TOOL-05 |
| 深色主题公式黑底黑字 | `Color.value` 取色错误 + 未声明 `color-scheme` | MD-06 |
| 列表项不解析加粗与公式 | 列表项被展平成纯文本 | MD-05 |
| `$x$` 不被识别为公式 | 启发式要求含运算符或数字 | MD-03 |
| 换图标后桌面不刷新 | 启动器图标缓存 | BLD-04 / 手工卸载重装 |
| 401 认证失败 | 继承了桌面端专用路由环境变量 | API-02 / ERR-02 |

## 11. 取舍说明

- **不做像素级视觉回归**：没有设计稿基线，靠「关键界面截图 + 人工比对」更实际
- **不做 Monkey 长稳 24 小时**：本机模拟器成本高，用 5 分钟 Monkey + 长会话滚动替代
- **不做真机自动化**：只有一台手机，USB 来回插拔成本高，真机只做手工清单
- **WebView 段落的选择行为不追求与原生一致**：这是实现方式的固有代价，记录而非修复
